# 原理与限制

## 问题的本质

Bambu Studio 从 PrusaSlicer 继承了一套"用户目录"（data dir）的概念，默认在：

```
%APPDATA%\BambuStudio
```

里面有配置、预设、插件缓存……以及**登录凭据**：

```
%APPDATA%\BambuStudio\BambuNetworkEngine.conf
```

这个文件是加密二进制，登录成功后由 `plugins\bambu_networking.dll` 写入。一个用户目录只能存一份凭据，所以一个 Windows 用户只能有一个"当前登录账号"。

常见的"多开"办法（再点一次图标、右键"以另一个用户身份运行"、多开工具）都**不会**换掉这个目录，所以打开的还是同一个账号，甚至只是把已有窗口切到前面。

## 本工具的做法

Bambu Studio 支持命令行参数 `--datadir <路径>`（`findstr "datadir" BambuStudio.dll` 可以直接看到这个字符串）：

```
bambu-studio.exe --datadir "D:\...\profiles\家里打印机" --datadir2 ...
```

给了这个参数，程序就把**整个用户目录**换成指定的路径，凭据也随之读写到那份目录里。于是：

| | 命令 | 用户目录 | 登录状态 |
|---|---|---|---|
| 默认账号（公司） | `bambu-studio.exe` | `%APPDATA%\BambuStudio` | 原封不动 |
| 独立账号（家里） | `bambu-studio.exe --datadir "...\profiles\家里打印机"` | 独立目录 | 各自一份 |

两个进程同时跑，两份凭据互不可见，也就不会互相顶号。

## 实测依据

这套结论不是猜的，是在真实环境里验证过的：

1. **数据目录确实被换掉**：用 `--datadir D:\test` 启动，35 秒内该目录里出现了独立的 `BambuStudio.conf`、`printers`、`system`、`user`、`logs`，而 `%APPDATA%\BambuStudio` 下两个 conf 的修改时间**完全没变**。
2. **凭据确实跟着目录走**：把现有数据目录整体复制一份，指向副本启动后，副本里的 `BambuNetworkEngine.conf` 被改写为运行时刻，且内容哈希与源文件完全一致（`9BFFE085...16DE2A1`）——说明插件是从 `--datadir` 指定的目录里读凭据的。
3. **可以同时跑**：两个不同 `--datadir` 的实例并存，进程都存活。
4. **同一目录会真的多开**：对同一份数据目录再启动一次，会多出一个独立进程（PID 不同）——所以本工具自己做了去重，避免账号状态打架。

## 边界与限制

- **只隔离登录状态，不隔离打印机**：每个账号能看到的设备，取决于该账号在拓竹云端绑定了哪些机器。
- **不绕过服务器规则**：同一个账号同时登录多处仍会互踢，这是服务端行为。
- **依赖 `%APPDATA%\BambuStudio` 的默认账号不被破坏**：本工具对默认账号只读不写；复制插件时还会主动删掉目标里的凭据文件。
- **目录结构随版本可能变化**：插件目录名（`plugins`/`ota`）来自当前版本实测。版本大改后如发现新窗口缺插件，删掉该账号的数据目录重新添加即可（会重新下载）。
- **不修改 Bambu Studio 安装文件**，不注入 DLL，不 hook 网络请求。
- **不支持"局域网模式"以外的特殊玩法**：本工具与连接方式无关，云端/LAN 模式都由 Bambu Studio 自身决定。

## 安全说明

- 程序不会发起任何网络请求（源码里没有 socket/HttpClient 调用）。
- 不读取 `BambuNetworkEngine.conf` 的内容——只判断文件是否存在、大小是否大于 0（用来显示"已登录/未登录"）。
- 复制目录时只处理 `plugins`、`ota`、`user`，并在结束时删除副本里的 `BambuNetworkEngine.conf`、`BambuStudio.conf`。
- 所有数据都在 `%APPDATA%\BambuMultiLauncher`，删掉即净。
## 为什么老版本 Bambu Studio 起不来

新账号第一次启动时，如果那个数据目录里的 BambuStudio.conf 还是空的或者写着 "single_instance": true，Bambu Studio 会把它当成"已经有一个实例在跑"：

- 新进程把启动请求转给一个不存在的窗口，然后自己退出；
- 表现出来就是"点了没反应"或者"窗口一闪就没了"。

本工具的启动诊断会自动处理这一步：有 conf 就备份成 .bak 后把值改成 false，没有 conf 就写一份最小的 {"single_instance": false}，然后再试一次。

新版 Bambu Studio（02.08 之后）默认就是 false，所以在新版上一般不会碰到。

## 两种启动方式，以及为什么要两种

打开 Bambu Studio 有两种等价于不同 Win32 调用的做法：

| 方式 | 实际调用 | 特点 |
|---|---|---|
| 双击方式 | `ShellExecuteEx`（`open` 动词） | 和你在资源管理器里双击快捷方式一模一样，走 shell 的关联与提权逻辑 |
| 常规方式 | `CreateProcess`（`Process.Start`） | 直接创建进程，能拿到句柄与参数，但绕过了 shell |

在部分电脑上，`CreateProcess` 直接拉起来的 Bambu Studio 会在几秒后自己崩掉（退出码 `0xC0000409`），而 `ShellExecuteEx` 不会——反过来也有。本工具默认"先双击方式、不行再常规方式"，并在窗口消失后自动换另一种重试一次；也可以在 **高级设置 → 启动方式** 里固定成某一种。

启动诊断会把两种方式各试一次，报告最后直接告诉你哪种能用。

## 旧数据是怎么被认回来的

启动时会扫这几类位置，把里面"看着像 Bambu Studio 数据目录"的子目录（有 BambuStudio.conf、BambuNetworkEngine.conf、plugins 之一）加进列表：

| 位置 | 说明 |
|---|---|
| %APPDATA%\BambuMultiLauncher\profiles | 本工具自己的 |
| %APPDATA% / %LOCALAPPDATA% 下一层叫 profiles 的目录 | 便携模式、以前改过路径 |
| 桌面 / 文档 / 用户目录下一层叫 profiles 的目录 | 以前把数据放桌面的人 |
| 以前那些脚本所在目录里的 profiles | 最早那版 PowerShell 脚本建的 home / work |

只读取目录结构，不读、不上传任何凭据内容。
