## 1. 产品背景（为什么要做这个）

### 1.1 真实用户场景

原开发者（本工具的起点）有两个拓竹账号：

- **公司的打印机**绑的是**同事的账号**——公司同事都习惯登那个号发任务，账号不能换绑；
- **家里的打印机**绑的是**他自己的账号**；
- 电脑只有一台（Windows），Bambu Studio **一次只能登录一个账号**；换账号 = 退出 → 重新登录 → 收手机验证码 → 输入。一天来回几次，还要找同事要验证码。

### 1.2 三条硬约束（决定了方案走向）

1. **手机应用双开没用**：他要发自己画的模型（本地 STL/3MF），而手机端 Bambu Handy 只能发 MakerWorld 上的开源模型。
2. **不能把打印机切到局域网模式**：还需要用手机 App 远程看打印机状态，局域网模式会失去云端能力。
3. **必须是 Windows**，且**不能改账号绑定关系**（公司账号是别人的）。

### 1.3 结论：唯一可行的路线

> **一个账号 = 一份独立的数据目录（`--datadir`）= 一个独立窗口**，登录态随目录隔离；默认账号继续用 Bambu Studio 原来的目录，什么都不动。

这条路线的关键前提是"登录态存在数据目录里的文件里"——这一点被实测确认，见第 2 节。

## 2. 技术原理（必须理解的 5 件事）

### 2.1 登录态到底存在哪

Bambu Studio 的数据目录（默认 `%APPDATA%\BambuStudio`）里：

| 文件/目录 | 作用 |
|---|---|
| `BambuStudio.conf` | 界面/偏好设置（JSON），**不含账号** |
| `BambuNetworkEngine.conf` | **登录凭据就在这**（加密二进制，704 / 768 字节量级） |
| `plugins\bambu_networking.dll` | 网络插件（云端通信全靠它，21–23 MB） |
| `printers\ ota\ system\ user\ log\ cache\` | 设备、OTA、预设、日志等 |

- 把数据目录整份复制到别处、用 `--datadir` 指过去，插件会**读并回写**那份 `BambuNetworkEngine.conf` → 目的目录的登录态与原目录**完全独立**。
- **只复制配置文件和 plugins，不复制 `BambuNetworkEngine.conf`**，新目录就是"未登录"的全新环境（工具创建新账号时就是这么做的，避免两份相同凭据互相顶号）。

### 2.2 `--datadir` 参数

Bambu Studio 是 PrusaSlicer 系，支持 `--datadir "<绝对路径>"`。
- 默认账号：**不传** `--datadir`（走 `%APPDATA%\BambuStudio`，保证"直接双击原版快捷方式"仍是同一个登录态）。
- 其他账号：传 `--datadir "<该账号目录>"`。
- 空目录启动也能跑，但会**重新下载网络插件**（几十秒到几分钟），所以"新账号第一次打开很慢"是正常的。

### 2.3 同一目录会真的多开 → 必须自己做去重

实测：对同一个 `--datadir` 连续启动两次，**会真的多出两个进程**（Bambu Studio 不是严格的单实例）。

因此工具自己维护：
- `state\p<账号id>.pid` 记录"上次启动的 PID"；
- 启动前 `IsAlive(pid)` + 进程名包含 `bambu` 校验，还活着就返回 `AlreadyRunning` 并只把窗口拉到前台；
- WMI 查询（`Win32_Process where Name='bambu-studio.exe'`）**只作兜底**——很多环境会"拒绝访问"。

### 2.4 `single_instance`：老版本"点了没反应"的真凶

02.09 版本的 `BambuStudio.conf` 里默认 `"single_instance": false`；但 **02.07 及更早的版本在没有 conf 的新目录里按 `true` 处理**：

> 新进程启动 → 检测到"已有实例" → 把启动请求交给那个"其实不存在的窗口" → 自己退出。
> 表现就是**双击之后一闪、什么都没发生**，用户以为工具坏了。

对策（`ProfileRepair`）：非默认账号在**启动前**检查它的 conf，把 `"single_instance": true` 原文改成 `false`（改前备份 `BambuStudio.conf.bak`，内容没变就不动）；没有 conf 就写一份最小配置 `{ "single_instance": false }`。幂等，可重复调用。

### 2.5 0xC0000409：Bambu Studio 自己崩

诊断里见过退出码 `-1073740791` = `0xC0000409`（Stack Buffer Overrun），是 **Studio 进程自身崩溃**，不是参数错误。已知诱因：

- 同一份数据目录被两个 Studio 同时写；
- 网络插件损坏/不完整；
- **启动方式**差异（见下）。

所以工具内置两种启动方式，并且可切换：

| 方式 | 实现 | 说明 |
|---|---|---|
| 双击方式（Shell） | `ShellExecuteEx`（`lpVerb=open`） | 等价于用户双击快捷方式，实测更稳 |
| 常规方式（Direct） | `Process.Start`（`UseShellExecute=false`） | 能精确拿到 PID/退出码，可传参 |

默认"自动"：先试双击方式，7 秒内进程消失就**自动换另一种方式重试一次**；高级设置里可固定成某一种。

### 2.6 登录列怎么判"已登录"

不能只看文件存不存在：**32 字节的空壳文件**（16 B 头 + 16 B 密文）会产生"已登录"的假象。

判据：`BambuNetworkEngine.conf` 长度 **≥ 48 字节** 才算已登录（真实样本 704 / 768 字节）。

## 6. 数据与配置

### 6.1 配置目录布局

```
%APPDATA%\BambuMultiLauncher\
├─ settings.ini        配置（UTF-8 带 BOM，可手改）
├─ logs\app-YYYYMMDD.log
├─ state\p<id>.pid     每个账号上次启动的 PID
└─ profiles\<账号名>\  非默认账号的独立数据目录（每份 ≈200–250 MB）
```

默认账号**不复制数据**，直接指向 `%APPDATA%\BambuStudio`。

### 6.2 `settings.ini` 结构

```ini
; 拓竹多账号启动器 配置文件
; 可以直接手动编辑，改完重新打开程序生效。
[app]
studioexe=C:\Program Files\Bambu Studio\bambu-studio.exe
extraargs=
profileroot=C:\Users\<你>\AppData\Roaming\BambuMultiLauncher\profiles
lastprofile=1
firstrun=1
remember=1
dedupe=1
autorefresh=1
launchmethod=0          ; 0=自动 1=双击方式 2=常规方式
windowx=..., windowy=..., windoww=900, windowh=560
ignoreddirs=C:\old\a|C:\old\b     ; 删掉的账号目录（`|` 分隔），不再被自动认回

[profile:1]
name=公司账号（默认）
dir=C:\Users\<你>\AppData\Roaming\BambuStudio
default=1
note=
```

- 键名大小写不敏感；`;` 和 `#` 是注释；布尔写 `1/0`。
- `dir` 支持相对路径，加载时会按配置目录归一成绝对路径。

## 7. 踩坑总结（**这份文档最值钱的部分**）

> 每条格式：**现象 → 根因 → 结论/对策**。接手时按主题扫一遍，能省掉几天。

### 7.1 架构 / 原理类

1. **复制了配置却没有登录态** → 登录凭据在 `BambuNetworkEngine.conf`（加密二进制），不在 `BambuStudio.conf` 里 → "搬迁账号"必须整目录复制（含 plugins/ota/user）。
2. **两份目录互相顶号** → 把同一个 `BambuNetworkEngine.conf` 复制成两份，等于同一账号两处登录 → 新账号目录**必须删掉凭据文件**，让它首次自行登录。
3. **新账号第一次打开特别慢/像卡死** → 空目录要重新下载网络插件（几十 MB）→ 不是 bug；`HasPlugins()` 会在提示里说明"首次会自动下载"。
4. **以为 Studio 是单实例** → 实测同一 datadir 连点两次进程数会变 2 → 必须自己用 pid 文件 + 进程名去重，不能依赖 Studio。
5. **老版本"点了没反应"** → 02.07 及更早在无 conf 的新目录默认 `single_instance: true`，把启动请求交给不存在的窗口后自退 → 启动前把 conf 改 `false`（备份 + 幂等）。
6. **32 字节文件被判"已登录"** → 空壳凭据（16 B 头 + 16 B 密文）→ 判据改为 ≥48 字节。
7. **退出码 -1073740791** → `0xC0000409`，Studio 自己崩，不是参数错 → 两种启动方式 + 自动换方式重试 + 诊断报告解释。

### 7.2 WinForms / UI 类

8. **向导底部莫名出现横向滚动条** → `FlowRow/FlowText` 收到的宽度**已经是像素**，却又套了一次 `Ui.Px()`（1593 = 1062×1.5）→ 宽度参数不要再缩放。
9. **`ListView.ItemHeight` 编译不过** → .NET Framework 的 ListView 没这个属性 → 用 `ImageList.ImageSize` 撑行高，或自绘。
10. **列表每 2.5 秒闪一次** → 定时器里 `Items.Clear()` 全量重建 → `BufferedListView`（双缓冲）+ 原地增量更新（只改变化的单元格）。
11. **多个 `Dock=Top` 上下颠倒** → 叠放顺序依赖 z-order → 用 `TableLayoutPanel` 显式分格。
12. **点"配置目录/日志目录"没反应** → ①`Process.Start(UseShellExecute=true)` 在某些宿主直接 `Win32Exception: 拒绝访问`；②即使打开了，资源管理器窗口被**模态对话框挡住** → 三级兜底（ShellExecuteEx → explorer.exe → cmd start）+ 枚举 `CabinetWClass` 窗口前置 + 状态行/弹框反馈。
13. **点启动后界面卡十几秒** → 同步 `BringToFront(pid, 10)` 轮询，而真实 Studio 要 19 秒才出窗口 → 改成 400 ms 异步 Timer、25 秒上限，主线程不阻塞。
14. **ComboBox 一加就冒出滚动条** → 内容宽度按 660 设计、竖向滚动条又吃掉 17 px → 内容宽留 640、窗体高补到 624（内容 560 + 底栏 60 + 余量）。

### 7.3 构建 / 语言类

15. **csc 报一堆语法错** → 系统自带 csc 只有 **C# 5** → 不能用字符串插值 `$"..."`、`?.`、`nameof`、表达式体成员、`out var`、元组、`_ = expr`。
16. **中文全变乱码** → 源码是无 BOM 的 UTF-8，csc 按 ANSI 读 → 编译必须加 `/codepage:65001`。
17. **PowerShell 脚本被解析成一堆 `Unexpected token`** → PS 5.1 读**无 BOM** 的 .ps1 按 ANSI 解码 → .ps1 存 UTF-8 **带 BOM**（注意 `edit` 类工具会抹 BOM，改完要补）。
18. **`build.bat` 报 `'需要' 不是内部或外部命令`** → .bat 被写成 LF 换行 → 必须 CRLF，第二行加 `chcp 65001 >nul`；`.gitattributes` 里已固定 `*.bat text eol=crlf`。
19. **编译报 `CS1567 生成 Win32 资源时出错` + `CS1610`** → `/out` 目录不存在 → 先建目录。
20. **winexe 用 `&` 启动后不等待、拿不到退出码** → 用 `cmd /c start /wait "" "exe" 参数` 再读 `$LASTEXITCODE`。

### 7.4 运行环境 / 验证方法类

21. **截图全是壁纸，看不到窗口** → 某些受限桌面里 `CopyFromScreen` 只拿得到桌面 → 改用 `--render`（`DrawToBitmap` 离屏出图）验收界面。
22. **`%APPDATA%` 不可写，程序"启动后没生成配置"** → 受限环境 → 用 `BAMBUMULTI_HOME` 指向可写目录；`--render` 现在也会自动隔离（`render-home`），不再改真实配置。
23. **WMI `Win32_Process` 报"拒绝访问"** → 不是程序 bug → 查询失败要静默降级（pid 文件 + 进程名），日志里只记一条 WARN。
24. **自检第二次跑同一目录会失败** → 残留文件影响 `HasLogin`、"无 conf 写最小配置"等用例 → 自检**必须用全新空目录**。
25. **自检里"启动去重"项被跳过** → sleep 桩要求放在**自检目录根**（`Path.Combine(dir,"bambu-sleeper.exe")`），放子目录不算。
26. **`cmd start` / `explorer` 启动 Studio 后完全看不到进程** → 受限环境下的假象，不能据此判断"启动失败" → 结论只能来自 `--selftest` / `--render` / 真实用户机。

### 7.5 数据 / 文件名类

27. **相对路径的账号目录，Studio 解析到别处** → Studio 以 exe 目录为基准 → `Settings.Load` 时统一 `GetFullPath` 到配置目录。
28. **删掉的账号每次启动又回来了** → 启动时无条件扫描旧目录 → 加 `ignoreddirs` 黑名单（删除时记、导入时跳过、手工添加时清除）。
29. **账号名填 `NUL` 后面直接报错** → Windows 保留名 → `SafeFolderName` 命中 CON/PRN/AUX/NUL/COM1–9/LPT1–9 时加 `_` 前缀；另外**只 Trim 空格和点**，不要 Trim 下划线（`a_b_c______` 要保留）。

## 9. 已知限制（不要当成 bug 修）

1. 必须已安装 Bambu Studio（工具不内置 Studio）。
2. **不能共享打印机**：账号与打印机的绑定关系不变，工具只解决"一台电脑登录多个账号"。
3. 打印机仍需**云端在线**（不依赖局域网模式）。
4. 每个非默认账号目录 ≈200–250 MB（复制插件与预设所致）。
5. 同一账号**不要在两份目录里反复登录**（会顶号，云端只认最后一次）。
6. 未做代码签名 → 首次运行会有 SmartScreen 提示（"更多信息 → 仍要运行"）。
7. 只在 110% 与 150% DPI 下验证过界面；其他缩放可能需要在 `Ui.Px()` 语义下微调。
8. Win10 未实测（只做了 API/框架层面的兼容推断）。
9. 只支持 Windows（WinForms + `csc`）；不支持跨平台。
10. 没有自动更新、没有托盘常驻、没有多语言。
11. 便携模式靠环境变量 `BAMBUMULTI_HOME`，没有做"配置文件跟随 exe"的开关。
12. 首次在新账号窗口里必须**手动登录一次**，之后由 Studio 自己记住。

## 12. 接手时**不要**做的事

1. ❌ 不要动真实用户的 `%APPDATA%\BambuStudio`（那是"默认账号"，一改就掉登录）。
2. ❌ 不要把 `dist\`、`build\`、`*.exe` 提交进 git（`.gitignore` 已排除，别手动 `git add -f`）。
3. ❌ 不要在同一个自检目录反复跑自检（会假失败）。
4. ❌ 不要用截图判断 GUI 是否正常（受限环境拿不到窗口），用 `--render`。
5. ❌ 不要把 `single_instance` 改成"永远 true"或删掉用户 conf——修补逻辑是"必要时改 false + 备份"。
6. ❌ 不要依赖 WMI 判断进程（很多环境拒绝访问），pid 文件 + 进程名才是主路径。
