# 拓竹多账号启动器 · 测试指南

配套文档：`docs/产品文档.md`（产品说明、原理、源码导览）
被测版本：v1.0.5（`dist\拓竹多账号启动器.exe`，约 155 KB，.NET Framework 4.x，无第三方依赖）

本文件是**可执行**的测试清单。每条都写了前置条件、操作、期望结果和判定方式。请按编号回报结果，例如 `T3.2 FAIL：两个窗口同时打开 6 分钟后，后打开的那个提示"已在别处登录"，另一个被踢`。

---

## 0. 环境准备

### 0.1 建议的测试环境矩阵

| 维度 | 建议覆盖 |
| --- | --- |
| 系统 | Windows 11 23H2（必测）、Windows 10 22H2（必测）、Windows 11 24H2（加分） |
| DPI | 100%（必测）、150%（必测）、125%、200%（加分） |
| Bambu Studio | 最新版（如 02.09.x）、**老版本 02.07.x**（必测，见 T5）、两台机器上装不同版本 |
| 账户 | 无 Bambu Studio 的干净机、装过但从未登录、装过且已登录、装过早期 PowerShell 版工具（见 T6） |
| 用户名 | 英文名（必测）、**中文名**（必测，见 T9） |
| 权限 | 普通用户（必测）、管理员（加分） |

### 0.2 每轮测试前的"干净状态"

```powershell
# 关掉所有 Bambu Studio
Get-Process bambu-studio -ErrorAction SilentlyContinue | Stop-Process -Force

# 备份并清空本工具的状态（保留 Bambu Studio 自己的数据，除非该用例要求）
Rename-Item "$env:APPDATA\BambuMultiLauncher" "BambuMultiLauncher.bak-$(Get-Date -Format yyMMddHHmmss)" -ErrorAction SilentlyContinue
```

还原：

```powershell
Remove-Item "$env:APPDATA\BambuMultiLauncher" -Recurse -Force -ErrorAction SilentlyContinue
Get-ChildItem $env:APPDATA -Filter 'BambuMultiLauncher.bak-*' | Sort-Object Name -Descending |
  Select-Object -First 1 | ForEach-Object { Move-Item $_.FullName "$env:APPDATA\BambuMultiLauncher" }
```

### 0.3 证据采集（每条失败用例都要带）

```powershell
# 1) 环境报告：高级设置 → 环境报告 → 复制全文（贴进报告）
# 2) 启动诊断：右键账号 → 诊断启动问题 → 复制全文
# 3) 日志
Get-Content "$env:APPDATA\BambuMultiLauncher\logs\app-$(Get-Date -Format yyyyMMdd).log" -Tail 80
# 4) 凭据指纹（验证账号隔离用）
Get-FileHash "$env:APPDATA\BambuStudio\BambuNetworkEngine.conf" -Algorithm SHA256
# 5) 正在运行的实例
Get-CimInstance Win32_Process -Filter "Name='bambu-studio.exe'" |
  Select-Object ProcessId, CommandLine | Format-List
```

### 0.4 判定用词

- **PASS**：与期望一致；
- **FAIL**：与期望不一致（请注明实际表现）；
- **BLOCKED**：环境不具备（写明缺什么）；
- 严重程度：`S1` 数据丢失/账号被顶掉/程序崩溃；`S2` 核心功能不可用；`S3` 体验/文案/排版；`S4` 建议。

## 3. 账号隔离（核心价值，T3）

前置：有两个不同拓竹账号（下称 A、B）。

| ID | 操作 | 期望 | 判定 |
| --- | --- | --- | --- |
| T3.1 | 用默认账号窗口登录 A（若未登录） | 能正常登录；`%APPDATA%\BambuStudio\BambuNetworkEngine.conf` 存在且非空 | — |
| T3.2 | 启动"家里打印机"窗口，登录 B（收验证码） | 新窗口独立登录成功，能看见 B 绑定的打印机 | — |
| T3.3 | **两个窗口同时开着** | 两个进程同时存在；各自的设备列表/账号头像不同；互不顶号（等待 ≥10 分钟再确认一次） | 若 B 登录后 A 被踢，记 FAIL/S1 |
| T3.4 | 关掉 B 窗口，再从主界面启动 B | 不需要重新登录（B 目录里的凭据还在） | — |
| T3.5 | 比较两份凭据哈希 | 两个账号目录的 `BambuNetworkEngine.conf` 哈希**不同**；默认账号目录的 mtime 在本工具启动默认账号时**不变** | — |
| T3.6 | 在 A 窗口改界面语言/主题，然后打开 B 窗口 | B 不受影响（各自 `BambuStudio.conf` 独立） | — |
| T3.7 | 删除 B 的目录（模拟数据丢失）后启动 B | 提示"这个账号的数据目录不见了…可以去高级设置换目录，或者删掉这个账号重新添加"（NoDir），不崩溃、不自动重建 | — |
| T3.8 | 把 B 的 `BambuNetworkEngine.conf` 删掉，看主界面"登录"列 | 变为"未登录"（橙）；重新启动 B 窗口要求登录 | — |

## 5. 启动兼容（T5，重点）

### 5.1 基本启动

| ID | 操作 | 期望 |
| --- | --- | --- |
| T5.1 | 双击"家里打印机"（新目录、首次） | 出现 Bambu Studio 窗口；若插件未就位，首次会慢（30–60 s），期间不应判为失败 |
| T5.2 | 观察主界面状态条 | 启动成功无红字；若工具补过 `single_instance`，提示"已经给…补上必要设置"；若没有插件，提示"第一次打开会自动下载" |
| T5.3 | 启动后 7 秒内手动关掉窗口 | 工具会提示"窗口没有起来"并询问是否诊断（这是预期行为，不算 bug）；点"否"后一切正常 |
| T5.4 | 启动默认账号 | 不传 `--datadir`；`%APPDATA%\BambuStudio` 的 `BambuStudio.conf` 不被本工具改写（mtime 只有当 Bambu Studio 自己写时才变） |

### 5.2 老版本 / `single_instance`

| ID | 操作 | 期望 |
| --- | --- | --- |
| T5.5 | 装 02.07.x（或更老）；新建账号目录里**没有** `BambuStudio.conf`；点启动 | 工具写一份最小的 `{"single_instance": false}`，窗口正常出现；目录里出现 `BambuStudio.conf`，内容含 false |
| T5.6 | 手工把某账号的 `BambuStudio.conf` 改成 `"single_instance": true`，再启动 | 启动前自动改回 `false`，同目录出现 `BambuStudio.conf.bak`；窗口正常 |
| T5.7 | 同上，但把 conf 里 `single_instance` 整行删掉 | 自动插入该字段并置 false；窗口正常 |
| T5.8 | 连续启动同一账号 3 次（每次关掉窗口） | 不会每次生成新的 `.bak`（幂等：内容已正确时不再改动、不新增备份） |
| T5.9 | **默认账号**的 `BambuStudio.conf` 是 `true`，启动默认账号 | 工具**不**改默认账号的 conf（设计如此）；若此时窗口一闪就没 → 记 FAIL 但注明"默认账号不修"是已知设计（见产品文档 10.2） |

## 14. 明确不要报的"非 bug"

- 默认账号目录不被复制/不被改名（设计）；
- 删除账号不删数据（设计，且有二次确认）；
- "登录"列基于凭据文件大小（≥48 字节算已登录；32 字节空壳显示"未登录"，这是设计）；
- 首次打开新账号慢（下载插件）；
- SmartScreen 提示未知发布者（未签名）；
- 只有中文界面；
- 不支持拖拽 3mf / 不做切片；
- `--render` 出的图标题栏是老式样式（`DrawToBitmap` 不画主题非客户区）；
- `--selftest` 在非空目录第二次运行可能失败（用新目录）。
