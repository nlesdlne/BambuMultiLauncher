# 常见问题

## 账号与登录

### 会不会顶号？

不会。每个账号用的是**完全独立的数据目录**，登录凭据 `BambuNetworkEngine.conf` 各存各的，Bambu Studio 之间互相看不见。

唯一会"顶号"的情况是**同一个账号**在两处同时登录——那是拓竹服务器端的限制，任何本地工具都绕不过去。所以：

- 一个窗口 = 一个账号，别在两个窗口里登同一个账号。
- 两个账号的窗口都开着没问题。

### 新窗口打开后是"默认账号"的状态，没让我登录？

说明这个账号的数据目录里已经有登录凭据了（通常是添加账号时，目录指向的还是默认目录）。检查列表里的"数据目录"一列：

- 应该是 `%USERPROFILE%\AppData\Roaming\BambuMultiLauncher\profiles\你的账号名`
- 如果显示的是 `...\Roaming\BambuStudio`，说明它和默认账号是同一个目录 → 删掉这个账号重新添加，选"新建一份独立目录"。

点击"打开目录"能直接看到该目录里是不是有 `BambuNetworkEngine.conf`。

### 提示"在别处登录" / 被强制退出登录？

同一个账号在别的地方登录了（手机 App、另一台电脑、或者同一份目录开了两个窗口）。改进办法：

- 确认同一个账号只在一个窗口里用。
- 如果是被手机 App 顶掉：Bambu Handy 和 Studio 用的是同一个账号体系，在 App 里退出再登回可能也会让 Studio 掉线，重新登一次即可。

### 每次都要重新登录 / 收验证码？

正常情况下只需要一次。反复要求登录通常是：

1. 那个账号的目录被清空或被"重置"了（删过 `BambuNetworkEngine.conf`）。
2. 目录放在网盘同步文件夹里，文件被同步工具改坏了。
3. 你在多个窗口/多台电脑反复登录同一个账号。

### 能同时登录三个以上账号吗？

能。每个账号一份目录，各开一个窗口。注意每份目录约 200 MB。

## 打印机

### 需要给打印机开局域网模式吗？

不需要。本工具完全不碰网络配置，Bambu Studio 仍然按原来的**云端模式**连接打印机，Bambu Handy 也照常能看打印机状态和摄像头。

局域网模式是另一条路（需要同网段 + 访问码），本工具用不到，也不建议为了多账号去开它。

### 打印机显示离线？

和本工具无关，是打印机 ↔ 云端的问题。确认打印机联网、账号里能看到这台设备、Bambu Studio 里刷新一下设备列表。

### 两个窗口能同时打印吗？

可以，一台打印机同时只执行一个任务，但两个账号可以各自对自己的机器下发任务。互不影响。

## 数据与安全

### 会不会把我的登录信息传到网上？

不会。程序只做一件事：用 `--datadir` 参数启动本机的 `bambu-studio.exe`。它不联网、不读也不上传任何凭据文件。源码全部公开，可以自己审。

### 复制插件时会不会把默认账号的登录状态带过去？

不会，这是刻意处理的：复制只针对 `plugins`、`ota`、`user` 三个子目录，复制完成后**主动删除**目标目录里的 `BambuNetworkEngine.conf` 和 `BambuStudio.conf`。自检里专门有一项测这个（`--selftest`）。

### 配置文件放哪？能手动改吗？

`%APPDATA%\BambuMultiLauncher\settings.ini`，纯文本 INI，可以直接编辑（改完重新打开程序）。日志在同目录的 `logs\`。

### 换电脑怎么把登录状态带过去？

关掉所有窗口，把 `%APPDATA%\BambuMultiLauncher` 整个拷到新电脑的同一位置。程序重新解压一份就行。

### 怎么彻底卸载？

删除程序目录 + `%APPDATA%\BambuMultiLauncher`。**不要删** `%APPDATA%\BambuStudio`——那是 Bambu Studio 自己的目录，本来就是你原来的账号。

## 兼容性

### Windows 提示"已保护你的电脑"（SmartScreen）

因为没有买代码签名证书。点"更多信息 → 仍要运行"。也可以自己用 `build.bat` 编译一份核对（源码保持一致，产物一致）。

### 杀毒软件报毒？

行为上它会启动别的程序（bambu-studio.exe），可能被启发式引擎误报。源码公开，编译命令在 `build.bat`，可以自行编译或提交给厂商申诉。

### 支持哪个 Windows 版本？

Windows 10 / 11（64 位），.NET Framework 4.x 是系统自带的，不需要额外安装。Windows 7 理论可编译运行，但未测试、不承诺。

### Bambu Studio 升级后还能用吗？

能。`--datadir` 是 Bambu Studio 从 PrusaSlicer 继承的稳定参数。如果某天升级后行为变了，点主界面的"检查环境"再看"环境报告"，把报告贴到 issue 里。

### 会不会和 Bambu 官方"多账号切换"功能冲突？

如果将来官方原生支持多账号，本工具就不需要了，届时按官方功能迁移即可。目前官方没有这个功能。
## 启动不了 / 适配问题

### 点了启动，窗口一闪就没了（或者干脆没出现）

先右键那个账号，点 **诊断启动问题…**。它会用两种启动方式各试一次，并在报告里写清楚：

- 进程活了多久、退出码是多少；
- 目标数据目录有没有被写入（没有写入 = 参数被忽略了）；
- 是不是 single_instance 这个开关在作怪；
- 哪种启动方式能起来；
- 进程还在的话，窗口到底出来了没有。

**Bambu Studio 是 02.07 或更早（老版本），新账号点了没反应？**

老版本在数据目录里没有 `BambuStudio.conf` 时会按默认值 `single_instance: true` 走：新进程把启动请求交给"已经开着的那个窗口"，然后自己退出——看起来就是点了没反应。1.0.3 起，本工具**每次启动前**都会把这一项确认成 `false`（改之前备份成 `.bak`）。

如果还不行，跑一次诊断，报告里会显示这个账号的 `配置文件 / 插件 / single_instance` 三行状态，把报告发我就能定位。

**看到退出码 `0xC0000409`（十进制 -1073740791）怎么办？**

这是 Bambu Studio 自己崩了（内部错误），不是参数传错。常见原因：

1. 已经有另一个 Bambu Studio 窗口在用同一份数据目录 —— 先把那个关掉再试；
2. 数据目录里的网络插件坏了 —— 在诊断里让它把 `single_instance` 修一下，或者干脆用"添加账号"新建一份目录、在里面重新登录一次；
3. 这台电脑上"直接创建进程"的方式起不来 —— 到 **高级设置 → 启动方式** 选"双击方式"，或者反过来选"常规方式"，再点一次启动。自动模式下也会自己换方式重试一次。

如果诊断显示"用常规方式能起来，双击方式不行"，那就是这台电脑的环境问题，把 **高级设置 → 启动方式** 固定成能用的那一种就行，以后一直生效。

Bambu Studio **02.07 及更早**的版本上更容易碰到单实例冲突，新版默认就是关掉的。

### 一直提示"找不到 Bambu Studio"

新版会把注册表翻一遍：App Paths、Classes\Applications、HKLM/HKCU 的 64/32 位卸载表、SOFTWARE 下名字带 Bambu 的键，再加上各固定盘的常见目录。

如果还是找不到（比如绿色版、解压到 U 盘里），到 **高级设置 → 浏览…** 手动指定一次即可。

### 电脑上有好几个 Bambu Studio，用哪个？

点 **高级设置 → 自动检测**，找到多个时会弹窗口列出来（带版本号），选一个就行。默认优先用你当前配置里那个，其次用版本号最高的。

### 以前装过（或用过那版 PowerShell 脚本），数据还在，会被覆盖吗？

不会。启动时会自动扫描下面这些地方，把以前留下的账号目录认回来，登录状态照旧：

- 本工具的 `profiles` 目录；
- `%APPDATA%` / `%LOCALAPPDATA%` 下名为 `profiles` 的目录；
- 桌面、文档、用户目录下一层的 `profiles`；
- 以前脚本所在目录里的 `profiles`（`home`、`work` 这类）。

认回来的账号会显示成"以前的账号（…）"，用不上的右键删掉就行（默认只从列表移除，不动数据）。
